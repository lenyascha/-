# Наём через HeadHunter — инструкция для Claude Code

Рабочая папка автономного найм-инструмента: 3 вакансии, HH API, локальная
БД. Читай этот файл в начале КАЖДОЙ сессии в папке (Claude Code — сам).
Всё, что не поместилось сюда, лежит в файлах ниже — читай их по ситуации.

**Как пользоваться этим набором файлов:** файлы из таблицы «Где что лежит»
НЕ импортируются `@путём` в этот CLAUDE.md — так они грузились бы в
контекст каждой сессии целиком, и раздутость, ради которой всё это
разложено, вернулась бы. Открывай их инструментом Read, когда текущая
задача попадает под триггер из таблицы. Не открывай «на всякий случай» всё
разом.

**Язык:** пользователю — всегда по-русски, независимо от языка вопроса.

**Кто есть кто:**
- Заказчик, финальное решение по кандидатам — Плаксин Д.А.
- Ты пишешь под HR-подписью «А. Терещенков» (имя владельца HH-аккаунта,
  `GET /me` — не выдумывать другое).
- HR-интервьюер (первичные встречи после теста) — по договорённости, имя
  своё или от заказчика.

## ⚠ Перед ЛЮБОЙ задачей — координация нескольких чатов (молча, без вопроса)

В папке могут параллельно работать несколько чатов, в т.ч. над разными
задачами. Не жди, пока пользователь опишет процесс — определяй сама.
Полная версия правила (мерж, вечно-эксклюзивные действия, откат) —
`.claude/rules/git-workflow.md`. Здесь — обязательный минимум перед стартом
работы:

1. Прочитать `.tasks/` (путь всегда абсолютный,
   `C:\Users\internet\Desktop\HRochka\.tasks\`, даже из чужого worktree) и
   `git branch --list "task/*"` / `git worktree list`.
2. Придумать слаг задачи самой (kebab-case, латиницей) — не спрашивать
   пользователя.
3. Не пересекается ни с одной активной записью `.tasks/` → завести
   `task/<slug>` от `master`, `.tasks/<slug>.md` по шаблону
   `.tasks/_TEMPLATE.md`, начать работу без подтверждения.
4. Пересекается — с чужой задачей ИЛИ со списком вечно-эксклюзивных
   действий (реальные действия на HH, `config/.env`/токен, старт/стоп
   `tg_bot2.py`, публикация тех.документации) — остановиться, спросить.

`.tasks/*.md` не версионируется git — живое состояние координации, не
история (историю несут ветки/коммиты).

## Тревожные звоночки (коротко — полная версия по ссылке)

- **HH отвечает 403 `bad_authorization` везде** → токен протух. НЕ пытайся
  обновить «на всякий случай» заранее — HH это запрещает
  (`400 invalid_grant`). `py code/refresh_token.py` сам проверит и обновит
  только если нужно. → `.claude/rules/hh-api.md`.
- **Разбор суммы зарплаты из текста кандидата** — НИКОГДА не пиши свой
  парсер, только `hh_core.parse_salary()`. Дважды ловили баги именно на
  самодельном разборе (крэш и ложные срабатывания на числах внутри
  кодов/ссылок). → `.claude/rules/hh-api.md`.
- **Собираешься отправить что-то кандидату/рекрутёру** (сообщение,
  отказ, карточка) → подпись/получатель/превью/не раскрывать вилку ЗП/
  причину отказа/проверить доставку — 5 пунктов, ни один не пропускать.
  → `.claude/rules/safety.md`.
- **6 контрактов зашиты в код** (`move_to_reject`/`move_to_assessment`
  бросают исключение при нарушении) — это не капризы, а уроки прошлых
  инцидентов. Полный список с обходами (`force=True` и т.п.) →
  `.claude/rules/hh-api.md`.
- **Правишь текст кнопки Telegram-клавиатуры?** Кнопки — обычный текст без
  callback_data: расхождение с диспетчером ломает кнопку ТИХО (нажимается,
  отвечает, но не туда). Проверяй `classify_admin_text` на новый текст. →
  `.claude/rules/telegram.md`.
- **Тех.документация (Artifact)** — НЕ обновлять и не переопубликовывать,
  если заказчик явно не попросил. → `.claude/rules/git-workflow.md`.
