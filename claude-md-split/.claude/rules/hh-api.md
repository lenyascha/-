# Правило: HH API — контракты и парсинг ЗП

Читай перед правкой `hh_core.py`, `funnel.py` или чего угодно, что вызывает
`move_to_*`/`parse_salary`/токен. Полное описание модулей —
`Документация/Архитектура.md`. Прошлые баги на эту тему — журнал инцидентов
пп. 2, 3, 5, 11, 18, 19, 26, 28.

## ⛔ Контракты (машина не даст нарушить — уроки прошлых ошибок, не капризы)

1. **`move_to_reject(...)` блокируется**, если кандидат уже в `interview`/
   `phone_interview` или `decision='interview'`, или за 7 дней был переход
   на след. этап. Обход — `force=True` + `decision_note` ≥10 символов.
   (Реальный случай: отказ ушёл ДО назначенной встречи, пришлось
   извиняться.)
2. **`move_to_assessment(...)` требует полный `scoring_json`** по 6
   критериям (`data, aiml, team, industry, lang, soft` + `final`) — формула
   в `Вакансии/<роль>/Регламент_найма.md`. Без него — исключение.
3. **`move_to_assessment(...)` требует пройденный salary-gate** — в HH-чате
   должен быть наш вопрос (`TMPL_SALARY_GATE_*`) и ответ кандидата с
   цифрой. `_salary_gate_passed()` — ТРИ состояния: `True`/`False`/`None`
   («нет связи с HH»). `None` блокирует так же, как `False` — НЕ как
   `True` (было багом: сетевой сбой снимал контракт).
4. **`hiring_status.py` — ЕДИНСТВЕННОЕ основание для «всё сделано».** Пока
   exit-код не 0 — работа не закончена.
5. **Разбор суммы ЗП — ТОЛЬКО `hh_core.parse_salary()`**, одна функция на
   весь проект (`funnel._parse_salary`/`tg_bot2._detect_salary` — обёртки
   над ней). **НЕ писать свой разбор** — двойной урок:
   - брало первое число в сообщении («Готов с 1 июля, зарплата 600» → 1
     000₽) — фикс: искать по денежным маркерам, не по позиции;
   - жадно матчило числа внутри кодов/идентификаторов («ОКВЭД 62.02, 28,5»,
     «FND-43730») — крэш или ложное «названа зарплата 43730». Фикс: сначала
     проверять форму числа, коды-с-тире исключены явным regex
     (`_ID_CODE_LEFT_RE`).
   `None` из неё = «НЕ РАСПОЗНАЛ», не «не назвал»: уходит рекрутёру
   (`funnel`→`salary_unclear`), не пропускается по воронке.
6. **Контекст для сообщений кандидату — ТОЛЬКО
   `Вакансии/<роль>/FAQ_кандидату.md`.** Подробности — `.claude/rules/safety.md`.

## HH-токен — как обновлять, чтобы не протухал

Токен живёт ~14 дней, потом любой запрос → 403 `bad_authorization`,
**воронка встаёт целиком** (стадия не хранится, восстанавливается из
переписки HH на каждом тике).

⚠️ **«Обновлять профилактически» НЕЛЬЗЯ.** На обновление живого токена HH
отвечает `400 invalid_grant / "token not expired"`, новую пару не даёт.
Порядок — **сначала проверить, потом обновлять**:
```bash
py code/refresh_token.py     # сам проверит /me; живой токен = exit 0, ничего не трогает
```
То же делает бот при каждом запуске (`tg_bot2._refresh_token_if_due(force=True)`).
Не вышло — пишет в admin-чат громко.

**Почему токен всё-таки теряется насовсем:** HH гасит старый
`refresh_token` в момент выдачи нового. Если процесс упадёт между ответом
HH и записью в `config/.env` — токен потерян навсегда (было 28.07.2026).
Поэтому `refresh_token.py` пишет новую пару СНАЧАЛА в
`data/.hh_token_backup.json`, потом в `.env`; следующий запуск пробует
резерв, если `.env` не сработал.

Не помогло — новый вход через браузер,
`ИНСТРУКЦИЯ_для_новичка.pdf` → «Если совсем протухло».

## Устаревший чат у повторно откликнувшихся

`applications` имеет UNIQUE на `(vacancy_id, resume_id)` — при повторном
отклике на перепубликованную вакансию новая строка НЕ создаётся, старая
остаётся с устаревшим `negotiation_id`. Перед ЛЮБЫМ обращением к HH-чату
(`get_messages`/`resend_message`/`change_collection`) код проходит через
`hh_core._live_neg_id()` — не обращайся к чату по `negotiation_id` из
строки напрямую, всегда через эту функцию. Полная история бага — журнал
инцидентов п.18.

## fetch_submission — allow-list и рейт-лимиты

Ссылки из сообщений кандидата — потенциальный SSRF: ходим ТОЛЬКО по
allow-list хостов (`_HOST_HANDLERS`). GitHub без токена = 60 запросов/час
на IP, при исчерпании — 403, неотличимо от закрытого репо без взгляда на
заголовки. Опциональный `GITHUB_TOKEN` в `config/.env` поднимает до
5000/час. Различать «наш сбой» и «вина кандидата» в `decision_note` —
см. `.claude/rules/safety.md`.
