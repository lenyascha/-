# Архитектура проекта

Справочник «как это устроено сейчас»: дерево репозитория, карта модулей, схема
БД. Не грузится автоматически в каждую сессию — читай целиком или по разделу
(`grep`/поиск по имени модуля), когда задача касается конкретного файла из
`code/`. Хронология решений («почему сделали именно так» с датами) —
`Журнал_решений.md`. Прошлые баги — `Журнал_инцидентов.md`. Обязательные
правила поведения — `.claude/rules/*.md`.

## Дерево (всё локально, без внешнего сервера)

```
config/.env          — секреты: HH-токен, (опц.) телеграм-бот
data/hiring.db        — SQLite, вся история кандидатов и решений
code/                 — весь код (hh_core.py, hiring_db.py, templates.py, ...)
Вакансии/<роль>/Регламент_найма.md — критерии и правила по каждой вакансии
Документы_HR/         — готовые шаблоны для HR-интервью (docx)
```

3 вакансии в работе — **все три равноценны, не пропускать третью**:
| role_code | Вакансия | HH vacancy_id |
|---|---|---|
| rac | Руководитель аналитического центра | 134764878 (перепубликована 01.07.2026, старый ID 132359929 в архиве) |
| piipl | Руководитель ИИ-платформы | 132370253 |
| arch | Архитектор данных и аналитических платформ | 134544725 |

## Установка и перенос на другой ПК

Тестов/линтера/сборки нет — набор автономных Python-скриптов, не пакет.
Установка одной командой — **`setup.bat` в корне** (двойной клик): ставит
пакеты, докачивает Chromium для playwright, создаёт недостающие папки,
накатывает схему `data/hiring.db`, переопределяет `PROXY_BIND_IP` под эту
машину, живыми запросами проверяет HH-токен, оба Telegram-токена и ключ
Anthropic. Отчёт по-русски, «блокеры / оговорки»; exit-код 0 = можно
запускать `run_bot.bat`.

Он же — диагностика при «что-то не работает»:
```bash
py code/setup_check.py                      # только проверить
py code/setup_check.py --install --write    # то же, что setup.bat
py code/setup_check.py --offline            # без сетевых проверок
```
`--write` чинит только безопасное (папки, схема БД, `PROXY_BIND_IP`,
`config/.env.example`). **Секреты не придумывает и не трогает.**

**Обязательно копировать при переносе** (остальное — код, в git/архиве):
- `config/.env` — единственное невосстановимое автоматически (секретный файл,
  не пересылать открытыми каналами);
- `data/hiring.db` — вся история кандидатов и решений;
- `Вакансии/**` — регламенты, FAQ, папки кандидатов (досье и дашборд
  сравнения собираются ТОЛЬКО из файлов папки кандидата, база тут не
  поможет).

После копирования: `setup.bat` → поправить, что назовёт блокером →
`run_bot.bat`. Единственная машинозависимая переменная — `PROXY_BIND_IP`
(локальный IP физического адаптера, см. `net_bind.py`); `setup_check.py`
определяет и прописывает сам.

Ручная установка, если `setup.bat` не подходит:
```bash
pip install -r code/requirements.txt   # requests, openpyxl, reportlab, pypdf, playwright, python-docx, docx2pdf
python -m playwright install chromium   # отдельный шаг: pip сам браузер не ставит
pip install faster_whisper              # только если нужна транскрибация
```
(`docx2pdf` требует установленный MS Word — им рендерится PDF чек-листа
после интервью.) Все скрипты запускаются из `code/`, сами читают
`../config/.env` и открывают `../data/hiring.db` — пути от файла модуля,
поэтому проект переносится в любую папку без правок.

## Карта модулей (code/)

⚙️ **Если в проекте настроен codegraph** (`codegraph_explore`/`codegraph
node`) — структурные вопросы («что вызывает X», «как A связано с B», «что
сломается при правке Y», «какие функции есть в модуле») задавай ЕМУ
напрямую: ответит точнее и по актуальному коду, не по этому статическому
списку. Список ниже намеренно НЕ пересказывает структуру кода — в нём
только то, что кодграф не скажет: единственные источники истины, вещи,
которые нельзя дублировать, обходы внешних багов, бизнес-смысл, не
написанный в самом коде. Поведенческие правила по темам — в `.claude/rules/`
(`hh-api.md`, `hiring-funnel.md`, `telegram.md`, `database.md`, `safety.md`).

- **`hh_core.py`** — ЕДИНСТВЕННОЕ место смены состояния отклика на HH: не
  дублировать вызовы `change_collection` в других модулях (кодграф покажет,
  кто её вызывает, но не саму эту договорённость). `move_with_message()` —
  обход бага HH API (пустое сообщение при смене коллекции, баг HH, не наш).
  Контракты воронки, построенные поверх этого клиента — `.claude/rules/hh-api.md`.
- **`hiring_db.py`** — весь доступ к `data/hiring.db`. Поиск кандидата по
  имени — `LOWER()` на стороне Python, НЕ SQL `LOWER()`/`LIKE`: встроенный
  `LOWER()` в SQLite не работает с кириллицей — гочи и почему так см.
  `.claude/rules/database.md`. `hh_core.py` пишет side-effects
  (`applications`/`activity_log`) синхронно с каждым действием на HH, не
  отдельным синком.
- **`sync_hh.py`** — забирает отклики с HH в базу. Однонаправленно HH→БД:
  обратной синхронизации нет, ВСЕ исходящие действия — только через
  `hh_core.py`, не отсюда.
- **`templates.py`** — ЕДИНСТВЕННОЕ место текста сообщений кандидатам
  (`TMPL_*` + подпись `SIG`) — не собирать текст inline в других модулях.
- **`funnel.py`** — чистая логика автопилота, к HH обращается ТОЛЬКО из
  `run_step` при `dry_run=False`. Полное поведение, автоотказы, потолки —
  `.claude/rules/hiring-funnel.md`.
- **`tg_bot2.py`** (~1500 строк, самый крупный модуль) — двухрежимный
  Telegram-бот: командный режим + стейт-машина кандидата + фоновые тики +
  singleton-lock (`data/.tg_bot2.lock` — не даёт запустить вторую копию,
  запуск/остановка ТОЛЬКО через `run_bot.bat`/`stop_bot.ps1`, не ручным
  `Stop-Process`). Полное поведение, два РАЗНЫХ источника встреч, кнопочные
  гочи — `.claude/rules/telegram.md`; структуру диспетчера и хендлеров —
  через codegraph, если настроен.
- **`llm_client.py`** — обёртка над Anthropic, `temperature=0`
  (детерминированность). Промпты жёстко расшифровывают сокращения вакансий
  (`rac`=РАЦ, `piipl`=РИИП, `arch`=Архитектор) и явно указывают:
  `salary_currency` в базе = `'RUR'` (легаси HH.ru), НЕ `'RUB'` — без этой
  подсказки модель придумывала другую расшифровку и обнуляла выборку.
  Ретрай (до 2 раз) на 408/429/5xx/529 и сетевых сбоях; 400/401/403 НЕ
  ретраятся, чтобы не маскировать настоящую причину.
- **`test_autoscore.py`** — автооценка сданного тестового. **Код НЕ
  переинтерпретирует регламент**: `RUBRIC_BLOCKS`/`THRESHOLDS`/`BLOCK_MAX` —
  дословная перепись `Регламент_найма.md`, без нормировки поверх. Итоговый
  балл и категорию считает КОД, у модели их не спрашивают — раньше сумма от
  модели расходилась с суммой блоков, и кандидаты падали из категории в
  категорию. `manual_anchors()` кладёт в промпт 2–3 РЕАЛЬНЫЕ ручные оценки
  той же роли — единственный носитель стандарта «на сколько тянет глубина»
  (методики оценки в проекте не существует).
- **`fetch_submission.py`** — читает то, что кандидат приложил ссылкой.
  SSRF-риск, allow-list хостов, `GITHUB_TOKEN` — `.claude/rules/hh-api.md` и
  `.claude/rules/safety.md`. Пределы размера файла считаются ПОСЛЕ разбора,
  не по сырому файлу — `.ipynb`/`.html` весят много именно из-за балласта
  (base64-картинки, минифицированный JS), который тут же выбрасывается;
  общий лимит по сырому размеру резал бы ровно те файлы, ради которых работа
  делалась.
- **`net_bind.py`** — привязка исходящих HTTP к `PROXY_BIND_IP` из `.env`.
  Нужна только при прокси + активном VPN одновременно (VPN иначе забирает
  маршрут по умолчанию на свой адаптер, и прокси молча перестаёт отвечать,
  хоть сам рабочий). Пустая переменная = поведение как без модуля.
- **`inbox_check.py`** / **`hiring_status.py`** — read-only отчёты, каждая
  секция печатает свой SQL. `hiring_status.py` = контракт 4
  (`.claude/rules/hh-api.md`): единственное основание для «всё разобрано».
- **`gen_rating.py`** / **`dashboard.py`** — `data/*.xlsx` и HTML-дашборд из
  тех же view, что в схеме БД ниже.
- **`recruiter_card.py`** — карточка кандидата + PDF резюме в Telegram
  HR-интервьюеру. Настройка — `.claude/skills/daily-ops/`.
- **`transcribe.py`** — обёртка над faster_whisper для распознавания
  записей/голосовых.
- **`postinterview.py`** — собирает папку кандидата после интервью. ⚠ Ждёт
  ОТДЕЛЬНУЮ транскрибацию голосовых комментариев рекрутёра — не то же
  самое, что транскрибация записи самого интервью (не путать источники, см.
  чек-лист оценки в `.claude/skills/daily-ops/`).
- **`fill_checklist.py`** — заполняет `Вакансии/Чек-лист_оценки.docx`,
  правила — `Вакансии/Регламент_заполнения_чек-листа.md`.
- **`hh_inbox.py`** — то, что не поймали три шага автопилота (вопросы,
  самоотказы, зависшая оценка). Pull, не push; жёсткая изоляция контекста
  от `Регламент_найма.md` — полное поведение `.claude/rules/telegram.md` и
  `.claude/rules/safety.md`.
- **`interview_scheduling.py`** — подбор времени первичного интервью +
  перенос уже назначенной встречи по инициативе рекрутёра —
  `.claude/rules/telegram.md`.
- **`outreach.py`** — партии кандидатов на превск HR-интервьюеру —
  `.claude/rules/telegram.md`.
- **`group_watch.py`** — слушает группу «МИУДОЛ: найм», отмечает показанные
  резюме — `.claude/rules/telegram.md`.
- **Внутренний контур импорта** (`internal_mail_poll.py` →
  `import_internal.py` → `internal_report.py`) — отдельная, полностью
  автономная параллельная воронка, НЕ пересекается с основной (HH), нигде
  больше не описана. Кандидаты внутренней кадровой платформы приходят НЕ
  через API (сети между контурами нет), а почтой: агент внутри закрытого
  контура дёргает REST API платформы и шлёт JSON/xlsx во внешний ящик,
  который отсюда вычитывается. Эти кандидаты по основной воронке НЕ
  ведутся; совпадение с HH — только мягкий флаг
  `possible_hh_resume_id`, решение о дубле — за человеком. Секреты —
  `IMPORT_MAIL_*` в `config/.env`, отдельно от `internal_agent/.env` (тот
  живёт внутри контура и сюда не попадает).
- **`replay_dialogs.py`** — офлайн-прогон выгрузки переписки через функции
  воронки, БЕЗ единого запроса к HH и отправки — read-only симулятор для
  проверки правок (тестов в проекте нет). ⚠ «Дней прошло» считается от
  сегодня — на старой выгрузке `test_overdue`/`salary_silence` почти всегда
  срабатывают, смотреть смысл только на свежей.
- **`gen_dossier.py`** — досье кандидата после интервью → HTML/PDF.
  Источник — ТОЛЬКО папка кандидата, база и HH не участвуют.
- **`gen_batch_dashboard.py`** — батч-дашборд «кто сдал тестовое». Причина
  «не вошёл» — КОНКРЕТНАЯ (`_explain_unmatched`), не общая фраза: разные
  случаи требуют разных действий от рекрутёра, а не «такого человека у нас
  нет».
- **`gen_comparison_dashboard.py`** — сравнение кандидатов ПОСЛЕ интервью.
  Рядом с рекомендацией ВСЕГДА печатается её источник (`rec_source`) —
  отметка рекрутёра или расчёт по баллам, выдавать одно за другое нельзя.
  Состав ОБОИХ дашбордов задаёт рекрутёр списком ФИО, автоотбора нет — см.
  `Документация/Журнал_решений.md`, 26.07.2026.
- **`name_match.py`** — ЕДИНСТВЕННАЯ реализация сравнения ФИО на весь
  проект — не заводить вторую копию этой логики в другом модуле (гочи и
  прецедент — `.claude/rules/database.md`). Фамилии на -ский/-цкий
  сравниваются по ОСНОВЕ, не целиком, иначе ломает и личные имена
  («Дмитрий»). Подстрочный поиск ЗАПРЕЩЁН.
- **`pdf_export.py`** — HTML→PDF через headless Chromium.
- **`group_cards.py`** / **`assessment_table.py`** — карточки/таблицы для
  группового просмотра. Потолок ЗП — ТОЛЬКО из `funnel.CEILING`, копий не
  заводить (была рассинхронизация: захардкоженное «500к у всех трёх» врало
  по 2 вакансиям из 3).
- **`refresh_token.py`** — обновляет HH-токен, `.claude/rules/hh-api.md`.
- **`setup_check.py`** — проверка окружения. Запущен ли бот — определяет
  ЛОКОМ `data/.tg_bot2.lock`, НЕ списком процессов (лаунчер `py` даёт два
  процесса на одного живого бота — по списку не отличить).

## Схема БД (data/hiring.db, code/schema_sqlite.sql)

SQLite-адаптация серверной Postgres-схемы (TIMESTAMPTZ→TEXT ISO8601,
JSONB→TEXT, без GIN — полнотекст через `LOWER()` в Python). Таблицы:
`vacancies` (3 роли), `candidates` (резюме с HH, `raw` — полный JSON),
`applications` (1 отклик = 1 связка vacancy+resume, `employer_state`/
`score`/`category`/`scoring_json`/`decision`), `activity_log` (журнал всех
переходов/сообщений), `assessments` (⚠️ легаси, не заполняется),
`tg_scheduling` (стейт-машина Telegram — слот интервью, НЕ пересекается с
`employer_state`), `interview_slots` (встречи, записанные рекрутёром
вручную — второй источник слотов, формат `'YYYY-MM-DD HH:MM'`;
`cancelled_at` вместо удаления, `reported_at` — вошёл в сводку),
`interview_scores` (оценки чек-листа ПОСЛЕ интервью), `test_axes_assessment`
(кеш LLM-оценки по 6 осям), `outreach_tracking` (партии на превск),
`interview_reschedule_requests` (перенос уже назначенной встречи). View:
`funnel` (сводка роль×стадия), `candidate_history` (полная история),
`cross_applicants` (кто откликнулся больше чем на 1 роль).

Подробности и гочи схемы (двойная шкала `score`, кириллица в `LOWER()`) —
`.claude/rules/database.md`.
