# Журнал инцидентов прошлых сессий

Баги и их фиксы — унаследовано, чтобы не повторять. Не грузится
автоматически; читай перед НЕТРИВИАЛЬНОЙ правкой соответствующего модуля
(номера сохранены как в истории проекта — не по порядку, т.к. пункты
добавлялись со временем; на них ссылаются `.claude/rules/*.md` и
`Архитектура.md`). Решения о новом поведении (не баги) — `Журнал_решений.md`.

1. Отказ ушёл кандидату ДО назначенной встречи следующего этапа → блокируется кодом (`.claude/rules/hh-api.md`, контракт 1).
2. Тестовое отправляли без выяснения ЗП → кандидаты отваливались на превске на несовместимой ЗП → salary-gate обязателен (контракт 3).
3. HH API: `PUT .../negotiations/{collection}/{id}` с полем `message` создаёт ПУСТОЕ сообщение (баг HH, не наш) — `hh_core.move_with_message()` обходит двумя раздельными запросами, руками так не делать.
4. Путали имя в переписке (написали «Андрей» вместо «Александр» Терещенкова) — сверять с `GET /me`, не по памяти.
5. HH-токен молча умирал через 2 недели без обновления — `refresh_token.py` + правило в `.claude/rules/hh-api.md`.
6. Встроенный `LOWER()` SQLite не работает с кириллицей — фильтры по городу/тексту молча возвращали 0 строк или мусор («кандидаты из Москвы» → 0 вместо сотен). Баг движка, не промпта — фикс только на уровне SQL/Python в `hiring_db.py`, промпт-инструкциям тут доверять бесполезно.
7. `full_name_lower` не пересчитывался при повторной синхронизации известных резюме (`sync_hh.py` не переобрабатывает старые записи) — у 81% базы регистр не был приведён к нижнему, точный поиск проваливался в фолбэк «по первым 4 буквам где угодно» и однажды подставил не того кандидата («Гулидов»→«Рогулин»). Риск реальный: та же функция в «отказ»/«пригласи». Больше НЕ сравнивать по подстроке — только `LOWER(full_name)` целиком или явные границы слов.

10. Кириллица в тексте `run_bot.bat` ломает разбор команд `cmd.exe` (не
    кодировка вывода — сам парсинг батника), алиас `python.exe` из Windows
    Store иногда зависает при старте нового консольного окна. Поэтому: текст

    при кириллице в самом скрипте), интерпретатор — через `py`-лаунчер или
    явный путь, не голый `python`, если есть шанс на стор-алиас.

23. **Сбой разбора голосовой оценки молча подменялся дефолтом, пересдача не
    подхватывалась.** Два разных бага в одной цепочке (`_handle_postiv`,
    `tg_bot2.py`), оба вели к «Чек-лист собран», но пустому/не по
    голосовому: (а) `llm_client.parse_checklist_voice` сама НЕ бросает
    исключение при сбое модели — ловит внутри, возвращает заглушку
    `{"scores": [3]*15, "recommendation": "MOZHNO", ...}` с `_error` в
    придачу, вызывающий код этот `_error` не проверял; (б) даже без сбоя
    модели: голосовое распозналось в пустую/почти пустую строку (тишина,
    обрыв записи) — `transcribe()` это не ошибка (вернёт `""`), модель на
    таком входе честно пытается выполнить инструкцию — возвращает
    правдоподобный JSON с нейтральными баллами, пустыми сильными/слабыми,
    БЕЗ `_error` вообще. Оба случая молча писали заглушку в чек-лист как
    настоящую оценку рекрутёра.
    Усугублялось третьим багом маршрутизации: как только заглушка
    «собиралась», стадия переходила в `await_approve` (ждёт «да»/«нет»
    текстом), а роутинг голосовых (`_handle_update`,
    `awaiting_assessment_voice`) считал голосовым-с-оценкой только стадию
    `await_voice` — попытка переслать голосовое ещё раз на этой стадии
    уходила МИМО пайплайна в общий разбор команд («🎙 Распознал:
    …»→«не понял команду») — выглядело как необъяснимая поломка пересдачи
    (раньше пересдача просто подхватывалась заново). Фикс из 3 частей: 1)
    обработка голосового вынесена в общую `_process_checklist_voice`,
    которая ДО вызова модели проверяет длину расшифровки
    (`_MIN_ASSESSMENT_VOICE_CHARS`) и ПОСЛЕ — `parsed.get("_error")`, в
    обоих случаях НЕ пишет чек-лист, просит голосовое заново, оставаясь на
    той же стадии; 2) в ответ на успешный разбор печатается сама
    распознанная фраза («Распознал: «…»») — видно, что чек-лист собран из
    сказанного, не угадан; 3) `await_approve` тоже принимает голосовое
    напрямую (не только явное «нет» текстом), обрабатывает как попытку
    переписать оценку — `awaiting_assessment_voice` включает обе стадии.
    Заодно — `checklist_from_transcript_start` (команда «чек-лист по
    Иванову»/`ADM_CHECKLIST_CONTINUE`): если транскрибация встречи уже в
