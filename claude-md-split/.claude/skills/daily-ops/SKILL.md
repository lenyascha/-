# Daily ops: установка, ежедневный ритуал, типичные операции

Не грузится автоматически в каждую сессию — вызывается по описанию выше или
командой `/daily-ops`. Архитектура/контракты — `Документация/Архитектура.md`
и `.claude/rules/`.

## Установка и перенос на другой ПК

Тестов/линтера/сборки нет — набор автономных Python-скриптов, не пакет.
Установка одной командой — **`setup.bat` в корне** (двойной клик): ставит
пакеты, докачивает Chromium, создаёт папки, накатывает схему БД,
переопределяет `PROXY_BIND_IP`, живыми запросами проверяет HH-токен, оба
Telegram-токена и ключ Anthropic. Отчёт «блокеры / оговорки»; exit-код 0 =
можно запускать `run_bot.bat`.

```bash
py code/setup_check.py                      # только проверить
py code/setup_check.py --install --write    # то же, что setup.bat
py code/setup_check.py --offline            # без сетевых проверок
```
`--write` чинит только безопасное (папки, схема БД, `PROXY_BIND_IP`,
`config/.env.example`). **Секреты не придумывает и не трогает.**

Обязательно копировать вручную при переносе (остальное — в git/архиве):
`config/.env` (секрет, не пересылать открытыми каналами), `data/hiring.db`
(вся история), `Вакансии/**` (регламенты, FAQ, папки кандидатов).

Ручная установка, если `setup.bat` не подходит:
```bash
pip install -r code/requirements.txt
python -m playwright install chromium   # отдельный шаг, pip сам браузер не ставит
pip install faster_whisper              # только если нужна транскрибация
```

## Ежедневный ритуал

Начало дня: `sync_hh.py` → `inbox_check.py`. По ходу дня — разбор секций.
Конец дня/сессии: `hiring_status.py` — exit 0 = можно отчитаться, что всё
разобрано.

```bash
cd code/
python3 sync_hh.py          # подтянуть новые отклики из HH в локальную базу
python3 inbox_check.py       # что нового по всем вакансиям (6 секций, с SQL под каждой)
python3 hiring_status.py     # 5 коридоров воронки; exit-код 0 = всё разобрано
python3 gen_rating.py all    # свежий рейтинг кандидатов в data/*.xlsx
python3 refresh_token.py     # обновить HH-токен, см. .claude/rules/hh-api.md
python3 hh_inbox.py          # переписка вне алгоритма: вопросы, самоотказы, просрочки
python3 hh_inbox.py rac --draft   # то же по одной роли, с черновиками ответов
```

Если держится запущенным `python tg_bot2.py` (авто-режим, см.
`.claude/rules/telegram.md`) — все read-пути (команды бота, карточки,
`hiring_status`) читают ту же локальную базу; пустая/устаревшая → сначала
синк (авто или ручной).

## Типичные операции из кода (не через бота)

```python
import sys; sys.path.insert(0, "code")
import hh_core, hiring_db, templates

# Найти кандидата
hiring_db.find_candidate_by_name("Иванов")
hiring_db.get_candidate_history(resume_id)

# Двинуть кандидата по воронке (варианты: move_to_consider/assessment/interview/reject)
# Контракты и обязательные поля — .claude/rules/hh-api.md
hh_core.move_to_assessment(neg_id, templates.TMPL_TEST_RAC.format(name="Иван"),
                            vacancy_id=134764878, resume_id="...",
                            score=8.1, category="A", scoring_json={...})

# Записать оценку СДАННОГО тестового (без смены коллекции на HH) — ЕДИНАЯ точка.
# Сама шлёт карточку кандидата заказчику в бот №2 (admin-чат) — не писать скоринг
# напрямую через hiring_db.set_scoring, иначе карточка не уйдёт. blocks: 5 блоков
# рубрики (depth/hypotheses/prioritization/visualization/management) + final(0..100).
hh_core.record_test_score(neg_id, blocks={"depth":18,"hypotheses":18,
                          "prioritization":18,"visualization":17,"management":18,"final":89},
                          category="A", decision_note="...стоп-факторы, что подготовлено...")
```

## Правила скоринга и тестовых — по вакансиям

Не держать в голове — открывать `Вакансии/<роль>/Регламент_найма.md` перед
КАЖДЫМ скорингом: стоп-факторы, потолок ЗП, правило по возрасту, веса
критериев, тестовое задание, пороги категорий. Для «Архитектор данных» —
раздел «Что не готово»: тестового задания ещё нет, это первое, что
доделать.

## Чек-лист оценки после HR-интервью

`Вакансии/Чек-лист_оценки.docx` заполняется из ДВУХ разных источников — не
путать: шапка (ФИО/дата/формат/длительность) из папки кандидата
(резюме+видео); 3 блока оценки+рекомендация+комментарий — из ОТДЕЛЬНОЙ, ещё
транскрибируемой записи голосовых комментариев самого рекрутёра (НЕ из
прочтения интервью). Полные правила, конвенция чек-боксов, скрипт
`fill_checklist.py` — см. `Вакансии/Регламент_заполнения_чек-листа.md`.
Блок оценки НЕ заполнять, пока нет транскрибации голосовых комментариев
рекрутёра.

## Telegram-карточки для HR-интервьюера (опционально)

`recruiter_card.py` собирает карточку кандидата + PDF резюме. Без
настроенного `TG_BOT_TOKEN`/`TG_CHAT_ID` в `config/.env` — просто печатает
текст+путь к PDF, копировать вручную. Для автоотправки — свой бот через
@BotFather, токен+chat_id в `config/.env`, дальше
`send_to_recruiter(neg_id, confirmed=True)` шлёт сам.
